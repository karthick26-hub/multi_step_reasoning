# Multi-Step Reasoning Agent with Self-Checking

A command-line reasoning agent that uses Gemini to create a concise plan, Python logic to solve supported structured word problems, and a Python verifier to validate the proposed result.

## Features

- **Planner:** calls Gemini to produce a concise numbered plan.
- **Executor:** uses deterministic Python logic for supported apple-count, train-duration, and meeting-slot questions.
- **Verifier:** independently validates quantities, time durations, and meeting-slot constraints.
- **Retry handling:** retries a failed verification a limited number of times, then returns a failed result.
- **JSON output:** returns an answer, status, short user-facing explanation, plan, verification checks, and retry count.
- **Tests:** the unit tests mock the Planner so they run quickly without depending on Gemini availability.

## Requirements

- Python 3.10+ recommended.
- A Google Gemini API key for live planning.
- Packages listed in `requirements.txt`.

## Setup (Windows PowerShell)

From the project directory:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Create a `.env` file in the project root:

```text
GEMINI_API_KEY=your_api_key_here
```

Do not commit `.env` or share your API key. The repository's `.gitignore` should include `.env`, `.venv/`, `__pycache__/`, and `*.pyc`.

## Run the agent

```powershell
python agent.py
```

Type a question at the prompt. Type `exit` to leave the interactive session.

Supported example questions:

```text
Alice has 3 red apples and twice as many green apples. How many apples does she have?
A train leaves at 14:30 and arrives at 18:05. How long is the journey?
I have free slots from 09:00-09:20, 10:00-11:00, and 13:00-13:30. Which slots can fit a 45-minute meeting?
```

The current executor is rule-based and only supports the problem types implemented in `executor.py`. Unsupported questions should return a failed status rather than a guessed answer.

## Run tests

```powershell
python -m unittest -v
```

The test suite patches `agent.create_plan`, so unit tests do not call Gemini and should run quickly. This validates the agent workflow and deterministic solving/verifying logic, but does not evaluate live Gemini plan quality. Run the separate connection check when you want to verify API connectivity:

```powershell
python gemini_connection_check.py
```

## Output schema

The agent returns a JSON object with these fields:

- `answer`: short final answer.
- `status`: `success` or `failed`.
- `reasoning_visible_to_user`: concise explanation; not a raw chain-of-thought transcript.
- `metadata.plan`: concise plan generated by the Planner.
- `metadata.checks`: verifier outcomes and details.
- `metadata.retries`: number of retries performed.

## Assumptions and limitations

- Times use a 24-hour `HH:MM` format.
- Overnight train durations are calculated by wrapping across midnight.
- Apple-count questions are supported when the number of red apples and the “twice as many green apples” relationship are present.
- Meeting-slot questions are supported when time ranges and a duration such as `45-minute` or `45 minutes` are provided.
- The Executor uses deterministic Python rules rather than an LLM. This keeps arithmetic and constraint checks predictable, but it means the system does not generalize to arbitrary word problems.
- The Planner depends on Gemini availability and API quotas. Temporary service errors can occur.
- Unit tests mock Gemini; the live connection check is separate.

## Design choices and future improvements

The Planner, Executor, and Verifier are separated to make each phase easier to test and replace. Arithmetic and constraints are handled by code for repeatability. The Verifier checks the computed intermediate values instead of trusting the explanation alone.

With more time, useful improvements include adding broader problem types, using structured output for the Planner, injecting a planner interface for easier tests, testing malformed times and boundary cases, adding timeout/backoff configuration, and recording a reproducible set of example logs from actual runs.
